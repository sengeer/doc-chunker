# doc-chunker

Семантическая нарезка больших текстовых документов на чанки под **контекстное окно LLM**.

`--size 16` означает **16K токенов** (16 × 1024 = **16 384 токена**), а не килобайты и не символы. Размер считается BPE-токенизатором `tiktoken`, в бюджет входит готовый выходной файл вместе с обёрткой формата (namespaces XML, скобки JSON, заголовок CSV и т.д.).

Границы чанка — структурные (абзац, элемент, ключ, строка таблицы), а не «ровно N токенов посередине слова». Небольшой выход за лимит (по умолчанию до 120%) разрешён, чтобы единица осталась осмысленной. Результат — обычные файлы того же расширения в `output/`, а не векторное хранилище.

## Установка (локально, с Python)

Нужен Python 3.11 или новее.

```bash
cd doc-chunker
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev,api]"
```

## Использование (CLI)

Положите файлы в папку `input/` и выполните:

```bash
doc-chunker --size 16
```

или:

```bash
python -m doc_chunker --size 16 --input input --output output
```

Для файла `input/document.xml` появятся `output/document_1.xml`, `output/document_2.xml`, … — каждый следующий чанк продолжает предыдущий.

### Аргументы

| Аргумент | Смысл |
| --- | --- |
| `--size K` | Размер окна в тысячах токенов. `16` → 16384 токена. |
| `--input` | Папка с исходниками (по умолчанию `input`). |
| `--output` | Папка для чанков (по умолчанию `output`). |
| `--encoding` | Кодировка tiktoken: `cl100k_base` (по умолчанию), `o200k_base`, `p50k_base`. |
| `--max-ratio` | Множитель мягкого лимита (по умолчанию `1.2`). |

## Docker (без Python на хосте)

На сервере нужен только Docker Compose.

```bash
git clone <URL_ВАШЕГО_РЕПО> doc-chunker
cd doc-chunker
docker compose up -d --build
```

Сервис слушает `http://HOST:8091`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/health` | Живость |
| `POST` | `/chunk` | Нарезка |
| `GET` | `/docs` | Swagger UI |

Тома по умолчанию: `./input` → `/data/input`, `./output` → `/data/output`.

Пример запроса:

```bash
curl -s -X POST http://127.0.0.1:8091/chunk \
  -H 'Content-Type: application/json' \
  -d '{
    "size": 16,
    "input_dir": "/data/input",
    "output_dir": "/data/output",
    "clear_output": true
  }'
```

Ответ:

```json
{
  "ok": true,
  "files": ["document_1.md", "document_2.md"],
  "messages": ["document.md → 2 чанк(ов)"],
  "count": 2
}
```

Для пайплайна с n8n можно смонтировать чужие папки, например:

```yaml
volumes:
  - /home/USER/projects/doc-check/processing:/data/input
  - /home/USER/projects/doc-check/chunks:/data/output
```

## Поддерживаемые форматы

| Расширение | Как режется | Что на выходе |
| --- | --- | --- |
| `.xml` | Дети корня; для WordprocessingML — абзацы и таблицы `w:body` | Валидный XML с теми же xmlns |
| `.json` | Элементы массива или ключи объекта | Валидный JSON |
| `.yaml`, `.yml` | Документы `---`, затем структура | Валидный YAML |
| `.toml` | Ключи верхнего уровня | Валидная таблица TOML |
| `.csv` | Строки данных | CSV с повторяющимся заголовком |
| `.html`, `.htm` | Блочные теги внутри `body` | HTML-документ |
| `.md` | Заголовки, затем абзацы | Markdown |
| `.txt`, `.log` | Пустые строки, затем строки | Текст |

Неподдерживаемые расширения пропускаются с сообщением в stderr, остальные файлы продолжают обрабатываться.

Файл, который целиком укладывается в бюджет, пишется как `имя_1.расширение`.

## Как это устроено

Приложение следует SOLID: pipeline зависит от абстракций `Splitter` и `TokenCounter`, форматы подключаются через реестр. Новый формат — новый класс с `extensions` и методом `split`, плюс регистрация в `SplitterRegistry.default()`.

Упаковка жадная и последовательная (O(n) по длине файла): это не bin-packing, порядок единиц сохраняется.

Токены считаются один раз на единицу и складываются со стоимостью обёртки. Погрешность BPE на стыках покрывается `max_ratio`.

Ограничение: файл целиком читается в память. Для образца на сотни килобайт этого достаточно; многогигабайтные документы лучше резать стримингом отдельно.

## Разработка

```bash
pytest
```
